# pi-ask-user-async

Pi のエージェントが選択肢付きの質問を行う extension です。選択肢に加えて自由入力もできます。回答を待つ同期モードと、独立した作業を続けられる非同期モードを備えています。

## インストール

GitHub から Pi パッケージとしてインストールできます。

```sh
pi install git:github.com/tesso57/ask
```

ローカルで試す場合は、このディレクトリで次を実行します。

```sh
pi -e ./extensions/index.ts
```

確認した環境は Pi 1.5.0 です。Pi の extension として動作し、通常のユーザー入力の代わりに自動で起動するものではありません。モデルが `ask_user` ツールを呼ぶと質問が表示されます。

## 使い方

エージェントに、必要なときは選択肢付きで質問するよう伝えてください。

- **async**: 質問を回答待ちとして表示し、ツールはすぐに戻ります。エージェントは回答に依存しない作業を続けられます。ユーザーは `/answer 1` のように表示された番号を指定して回答します。番号を省いた `/answer` では回答待ちの番号を確認できます。不要になった質問は `/ask-dismiss 1` のように番号を指定して取り下げられます。取り下げは回答や承認として扱われません。実行中の回答は次の機会にエージェントへ伝わり、待機中の回答は新しいターンを開始します。
- **sync**: 選択または自由入力を待ってからツールが戻ります。回答なしでは進められる作業がない場合に使います。エージェントの停止時には質問画面も閉じます。

Escape または空の自由入力は未回答として扱います。非同期の回答は Pi がユーザーメッセージとして受け付けるまで回答待ちに残ります。認証エラーなどで送信できなかった場合は、問題を解消してから同じ `/answer` コマンドで再回答できます。他の extension が回答を完全に書き換える、複数の質問の回答を一つのメッセージにまとめる、または入力を受け取って処理を終了する場合、回答待ちが残ることがあります。

非同期の質問はセッション履歴に保存され、再読み込みや再起動後に復元されます。セッションの切り替えや履歴ツリーの移動では、移動先のブランチにある未回答の質問を表示します。`--no-session` では再起動後に復元できません。質問と回答の送信記録は Pi のセッションファイルに保存されます。

print/JSON モードなど UI のない環境では、質問できない旨を返します。RPC クライアントでは通知、ウィジェット、コマンド、選択ダイアログへの対応が必要です。

後で回答が必須になる質問でも、待つ間に進められる作業があれば async を使えます。非同期で独立した作業を続けること、回答が必要な作業を待つことはモデルへの指示に依存します。extension 自体が後続の操作を強制的に制御するものではありません。

## 開発

開発と CI では、`.nvmrc` に記載した Node.js 26.13.0 を使います。Pi 1.5.0 の実行要件は Node.js 22.19.0 以降です。

```sh
nvm install
nvm use
npm ci
npm run typecheck
npm test
npm run check:package
npm run test:integration
```

`npm test` は Pi 本体による extension の読み込みも確認します。`test:integration` は Python 3 とローカル模擬モデルを使い、RPC 経由の質問・回答・取り下げを確認します。いずれも実際の LLM やユーザーの Pi 設定には接続しません。
